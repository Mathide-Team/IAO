# Internationalisation (issue #51)

IAO utilise **GNU gettext**. Le français est la **langue source** : les `msgid`
sont les libellés français, une chaîne non traduite s'affiche donc toujours en
français.

## Arborescence

```text
lang/
├── LINGUAS                      liste des locales (SEULE liste du projet)
├── messages.pot                 catalogue source, généré
├── <xx>.po                      une traduction par locale (29 au départ)
└── <xx>/LC_MESSAGES/iao.mo      catalogue compilé, chargé par l'application
```

| Fichier | Rôle |
|---|---|
| `lib/i18n.js` | Fonctions pures : lecture des `.mo`, règles de pluriel (sans `eval`), `gettext`/`ngettext`/`pgettext`, choix de la locale, extraction des chaînes d'`index.html` |
| `main.js` | Canal IPC `i18n:catalog` : lit le `.mo` de la langue demandée |
| `assets/app.js` | `applyTranslations()` traduit le DOM statique ; `window.iaoT()` pour les libellés construits en JavaScript |
| `scripts/i18n-update.sh` | Extraction (`xgettext` + extracteur HTML), `msgmerge`, `msgfmt --check`, compilation, rapport |
| `scripts/i18n-extract-html.js` | Textes, `title`, `placeholder`, `aria-label` et `alt` d'`index.html` |
| `.github/workflows/i18n.yml` | Vérification en CI et PR automatique de synchronisation |

## Choisir la langue

Lot 1 : l'interface reste en français par défaut. Pour une autre langue :

```bash
IAO_LANG=en npm start            # ou : iao --iao-lang=en
```

`IAO_LANG` accepte une liste ordonnée (`pt_BR:en`) ; la correspondance se fait
sur la locale exacte puis sur la langue seule (`pt_BR` → `pt`). Une locale
absente ou un catalogue illisible retombe sur le français (avertissement dans
`iao.log`).

## Mettre à jour les catalogues

Prérequis : GNU gettext (`sudo apt install gettext`) et Node.js.

```bash
npm run i18n:update     # régénère messages.pot, met à jour les .po, compile les .mo
npm run i18n:check      # mode CI : ne modifie rien, échoue si lang/ est en retard
```

`msgmerge` conserve les traductions existantes. Une nouvelle chaîne arrive avec
`msgstr ""` ; une chaîne modifiée peut devenir `#, fuzzy` (proposition à
relire, ignorée par `msgfmt` tant que le drapeau est présent). **Aucune
traduction automatique** n'est ajoutée par les scripts.

Le script affiche (et recopie dans le résumé GitHub Actions) l'état par locale :
traduites, non traduites, floues, compilée.

## Traduire

1. Ouvrir `lang/<xx>.po` (Poedit, Lokalize, ou un éditeur de texte).
2. Remplir les `msgstr`, retirer `#, fuzzy` après relecture.
3. `npm run i18n:update`, puis commiter `lang/<xx>.po` **et**
   `lang/<xx>/LC_MESSAGES/iao.mo`.

## Ajouter une langue

1. Ajouter le code dans `lang/LINGUAS`.
2. Si sa règle de pluriel n'est pas la règle germanique (`n != 1`), l'ajouter
   à `plural_forms()` dans `scripts/i18n-update.sh`.
3. `npm run i18n:update` crée `lang/<xx>.po` et le `.mo`.
4. Traduire, puis lancer la CI.

Aucun code applicatif à modifier : `main.js` ne connaît que les catalogues
présents sur disque.

## Rendre un libellé traduisible

- **HTML statique** (`index.html`) : rien à faire, l'extracteur relève les
  textes et les attributs `title`, `placeholder`, `aria-label`, `alt`.
- **JavaScript** : `window.iaoT('Libellé')` dans `assets/app.js` (repérable
  par `xgettext`, mots-clés `_`, `gettext`, `ngettext:1,2`, `pgettext:1c,2`).
  Commentaire pour les traducteurs : `// TRANSLATORS: ...` juste au-dessus.

## Packaging

`lang/` est embarqué tel quel par `electron-packager` et `electron-builder`
(motifs existants) : une nouvelle langue est livrée sans changer le packaging.

## État (lot 1)

- Infrastructure complète, 29 locales, CI.
- Interface statique d'`index.html` : 75 chaînes, traduites en anglais.
- Restent en français : libellés construits par `assets/app.js` (cartes de
  comptes, toasts, ordonnanceur...), à faire passer par `window.iaoT()` dans
  les lots suivants. La bascule automatique sur la langue du système viendra
  quand ils seront traduits.
